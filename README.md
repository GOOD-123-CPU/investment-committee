# Investment Committee

**AI-assisted investment research terminal with deterministic market metrics, specialist agents, adversarial debate, risk review, and CIO-style synthesis.**

Built with Next.js, React, TypeScript, Prisma/SQLite, Bun, and OpenAI-compatible model providers.

[![CI](https://github.com/GOOD-123-CPU/investment-committee/actions/workflows/ci.yml/badge.svg?branch=main)](https://github.com/GOOD-123-CPU/investment-committee/actions/workflows/ci.yml)

> This repository is a research/engineering project. Generated analysis is not financial advice, and model output should not be treated as authoritative market data.

## Why this project

A useful AI research terminal should separate **facts that software can compute or retrieve** from **interpretation generated by models**.

Investment Committee follows that boundary:

- market/portfolio data and quantitative indicators are produced by the application data layer and deterministic code;
- specialist agents interpret the shared data pack from different perspectives;
- bull/bear agents debate the strongest opposing cases instead of producing one unchallenged narrative;
- risk review and CIO-style synthesis operate on the collected evidence;
- authoritative numeric metrics are written back from code after model execution so a model cannot silently replace them with invented values.

For example, the Quant Agent may explain valuation and momentum, but the final `valuation` and `momentum` fields are overwritten with the metrics calculated by code in `src/lib/pipeline/agents.ts`.

## Research pipeline

```text
Market / security data
        |
        v
Normalized data pack + deterministic quant metrics
        |
        +---------------- specialist analysis ----------------+
        | fundamentals | industry | macro | quant | sentiment |
        +-------------------------+----------------------------+
                                  |
                                  v
                         Bull / Bear opening
                                  |
                                  v
                         Rebuttal + cross attack
                                  |
                                  v
                              Risk review
                                  |
                                  v
                        CIO-style synthesis
                                  |
                                  v
                 Research record / comparison / portfolio UI
```

The application also includes watchlists, recent research, security comparison, index knowledge, market terminology, portfolio analysis, and a terminal-style research interface.

## Engineering boundaries

### Deterministic data owns numeric truth

The model is allowed to explain code-computed metrics, but selected quantitative fields are force-written from the deterministic calculation result after the model call. This reduces a common failure mode where an LLM changes a number while paraphrasing it.

### Agents share evidence, not independent realities

Agents receive a structured data pack and explicit role constraints. Their disagreement is intended to expose competing interpretations of the same available evidence rather than to manufacture additional facts.

### Every model path has a fallback

Agent helpers return structured fallbacks when providers fail, so a single model/API failure does not need to make the whole research view unusable. Availability still depends on configured upstream market-data and model services.

### Debate is a workflow, not proof of better analysis

Multi-agent debate is an engineering mechanism, not evidence that the final report is automatically more accurate. A rigorous effectiveness claim would require a fixed evaluation set comparing single-agent, parallel-agent, debate, and debate-plus-review configurations on factual errors, unsupported claims, risk coverage, latency, and token cost.

## Main modules

| Area | Location | Responsibility |
| --- | --- | --- |
| Agent definitions | `src/lib/pipeline/agents.ts` | Specialist analysis, bull/bear debate, rebuttal, cross-examination, risk/CIO reasoning |
| Research API | `src/app/api/research/` | Research execution and persisted research records |
| Portfolio API | `src/app/api/portfolio/` | Portfolio analysis workflows |
| Research UI | `src/components/research/` | Agent, debate, decision, report, and comparison views |
| Database | `prisma/` | Local application data model |
| Seed universe | `db/seed/universe.json` | A-share, Hong Kong, and U.S. security discovery seed |

## Features

- Global market dashboard with index monitoring and quote views
- Multi-specialist research pipeline
- Bull / bear opening arguments, rebuttal, and cross-examination
- Risk review and CIO-style synthesis
- Deterministic valuation / momentum metrics with model interpretation
- A-share, Hong Kong, and U.S. market discovery
- Index encyclopedia and market slang dictionary
- Watchlist, recent research, comparison, and portfolio workflows
- Optional MiMo-compatible provider for deeper reasoning paths
- Local Prisma + SQLite persistence

## Getting started

```bash
bun install
cp .env.example .env
bun run db:push
bun run dev
```

Open `http://localhost:3000`.

### Environment variables

`DATABASE_URL` is required for Prisma. `MIMO_API_KEY` is optional unless you enable the MiMo provider or scripts that generate MiMo-backed candidates.

```env
DATABASE_URL="file:./db/custom.db"
MIMO_BASE_URL="https://api.xiaomimimo.com/v1"
MIMO_API_KEY=""
MIMO_MODEL="mimo-v2.5"
```

## Data notes

The repository includes a local seed universe at `db/seed/universe.json`. Runtime quotes, prices, news, and related fields are fetched through the application data layer and may depend on third-party service availability and upstream data quality.

Model-generated conclusions should be checked against the structured evidence shown in the application. Missing upstream data should be treated as missing evidence, not filled with invented precision.

## Current verification scope

GitHub Actions now performs a frozen Bun install, Prisma Client generation, ESLint, and a full Next.js production build. The first CI runs also exposed that standalone WebSocket examples and Bun maintenance scripts were unintentionally included in the web application's TypeScript compilation boundary; the app config now keeps those independent tools out of the Next.js type-check.

The successful verification run is [CI #3](https://github.com/GOOD-123-CPU/investment-committee/actions/runs/35949480896).

Automated unit coverage is still less mature than the build verification. The next high-value additions are deterministic tests for quant calculations, agent-output normalization, and pipeline failure/fallback paths.
